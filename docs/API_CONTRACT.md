# Контракт ML-сервиса — v0.1 (черновик на обсуждение)

**От:** ml (Svalbard1) · **Кому:** бекенд — Лиза, Валя · **Дата:** 2026-11-09

**Статус:** HTTP-эндпоинты v0.1 реализованы, покрыты тестами и прогнаны по чеклисту приёмки. Поиск по документам работает, генерация ответа — заглушка (`llm: "stub"`).
Живая документация (генерируется из того же кода): **http://localhost:8001/docs** — открой, там те же схемы, что ниже.

> Правило: любое изменение этого файла или `ml/service.py` — только через PR, который ревьюят и ml, и backend. Бекенд не коммитит в `ml/`, ml не коммитит в `backend/`.

## Общие положения

- Base URL: `http://localhost:8001` (в docker-compose — `http://ml-service:8001`)
- Всё JSON в кодировке UTF-8, кроме загрузки файла (`multipart/form-data`)
- Аутентификации нет: сервис внутренний, наружу не торчит. Если понадобится — добавим заголовок `X-API-Key` (см. «Зарезервировано под v0.2»)
- Любая ошибка приходит как `{"detail": "человеческое описание"}` (стандарт FastAPI) — бекенду достаточно показать `detail` в лог или пользователю

## GET /health

Живость сервиса и состояние индекса. Можно дёргать часто (health-пробы, статусная страница).

```bash
curl http://localhost:8001/health
```

Ответ `200`:
```json
{
  "status": "ok",
  "chunks_indexed": 55,
  "embed_model": "BAAI/bge-m3",
  "llm": "stub"
}
```

| Поле | Значение |
|---|---|
| `status` | всегда `"ok"`, если сервис ответил |
| `chunks_indexed` | сколько чанков лежит в индексе сейчас |
| `llm` | `"stub"` — генерация-заглушка; `"vllm"` — подключён настоящий LLM |

## POST /ingest

Принимает документ, режет на чанки, считает эмбеддинги, кладёт в индекс.

- Content-Type: `multipart/form-data`, одно поле `file`
- Разрешённые форматы: `.pdf`, `.docx`, `.txt`, `.md`
- Лимит размера: **25 МБ**
- Файл сохраняется в `ml/data/uploads/` (в git не попадает; в контейнере — volume)
- `doc_id` — стабильный (uuid5 по имени файла): тот же файл → тот же `doc_id`

```bash
curl -F "file=@пример.txt" http://localhost:8001/ingest
```

Ответ `200`:
```json
{
  "doc_id": "9f1c3e64a2b34d7e8c1fa5d60b8e4217",
  "filename": "пример.txt",
  "chunks": 6,
  "status": "indexed"
}
```

| Код | Когда |
|---|---|
| `400` | формат не поддерживается; в файле не найден текст (пустой документ, скан без текстового слоя) |
| `413` | файл больше 25 МБ |
| `500` | ошибка индексации (причина — в `detail`) |

⚠️ **Сейчас эндпоинт синхронный:** ответ приходит только после полной индексации, на большом PDF это десятки секунд. Асинхронный вариант (202 + статус) — в v0.2.

✅ Повторный `/ingest` того же файла **безопасен** — документ обновляется по стабильному `doc_id`, дубликаты чанков **не создаются** (идемпотентность проверена тестом и пунктом 11 чеклиста). Дедупликация по хэшу содержимого (один документ под разными именами = разные `doc_id`) — v0.2.

## POST /ask

Вопрос → топ-K релевантных фрагментов + ответ.

```bash
curl -X POST http://localhost:8001/ask \
  -H "Content-Type: application/json" \
  -d '{"question": "какая неустойка за просрочку поставки", "top_k": 3}'
```

Запрос:
```json
{
  "question": "какая неустойка за просрочку поставки",
  "top_k": 3
}
```

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `question` | string | да | от 3 до 2000 символов |
| `top_k` | int | нет | сколько источников вернуть, от 1 до 20, по умолчанию 3 |

Ответ `200`:
```json
{
  "answer": "Вопрос: какая неустойка за просрочку поставки\n\nНайдено 3 фрагментов. Генерация LLM ещё не подключена (llm=stub), ниже — выдержки из источников:\n1. [пример.txt, score=0.692] 4.1. За просрочку поставки Покупатель вправе потребовать неустойку в размере 0,1%...",
  "sources": [
    { "file": "пример.txt", "text": "4. ОТВЕТСТВЕННОСТЬ СТОРОН. 4.1. За просрочку поставки Покупатель вправе потребовать неустойку в размере 0,1% от стоимости товара за каждый день просрочки...", "score": 0.692 },
    { "file": "пример.txt", "text": "2.3. Остаток стоимости оплачивается в течение 10 рабочих дней после подписания акта приёмки.", "score": 0.514 }
  ],
  "took_ms": 812,
  "llm": "stub"
}
```

| Поле | Описание |
|---|---|
| `answer` | пока (`stub`) — выжимка найденных фрагментов, НЕ сгенерированный текст. Формат поля финальный: когда подключим vLLM, содержимое станет настоящим ответом, структура не поменяется |
| `sources` | список фрагментов, отсортирован по `score` по убыванию |
| `sources[].text` | текст чанка (обычно до ~500 символов) |
| `took_ms` | время обработки на стороне ML, мс |
| `llm` | `"stub"` / `"vllm"` — по этому полю фронт может показывать плашку «демо-режим» |

| Код | Когда |
|---|---|
| `422` | невалидный запрос: нет `question`, короче 3 символов, `top_k` вне диапазона 1–20 |
| `404` | по запросу ничего не найдено |
| `503` | индекс пуст — сначала должен быть вызван `/ingest` |

## Таймауты и лимиты (сводно)

| Эндпоинт | Обычное время ответа | Таймаут, который ставить бекенду |
|---|---|---|
| `GET /health` | < 1 с | 5 с |
| `POST /ingest` | 2–60 с (зависит от PDF и CPU) | 180 с |
| `POST /ask` | 1–3 с с заглушкой; с vLLM — до 30 с | 90 с |

- Первый запрос после старта сервиса медленный: модель эмбеддингов грузится в память (~5–20 с). Рекомендация бекенду: после старта сделать один прогревочный `/ask`.
- Лимит размера файла: 25 МБ.

## Ограничения v0.1 — прочитать обязательно

1. `llm` всегда `"stub"` (пока не подключён vLLM): `answer` — выжимка источников, не сгенерированный текст.
2. `/ingest` синхронный и без дедупликации (повторная загрузка = дубликаты чанков).
3. Сервис работает **только в одном экземпляре** (uvicorn без `--workers`, один контейнер): встроенное хранилище Qdrant не рассчитано на несколько процессов над одним путём.
4. Индекс и загруженные файлы живут в volume контейнера: без volume рестарт = индекс с нуля.
5. CORS открыт для всех (`*`) — dev-режим; сервис внутренний, напрямую от пользователей запросы к нему не приходят.

## Зарезервировано под v0.2 (обсуждаем заранее, до реализации)

- `X-API-Key` между бекендом и ML
