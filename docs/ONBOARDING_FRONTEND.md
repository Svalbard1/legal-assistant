# Онбординг фронтенда — Гульсым

Проект **legal-assistant**: ИИ-ассистент для юристов банка. Юрист задаёт вопрос в чат → система находит фрагменты в документах → показывает ответ и ссылки на источники. Кейс ПСБ × Changellenge, Hack&Change 2026.

Репозиторий: https://github.com/Svalbard1/legal-assistant.git (публичный). Твоя зона — папка `frontend/`.

## 1. Разовая настройка Git (~15 минут, один раз)

```bash
git config --global user.name "Имя Фамилия"
git config --global user.email "почта-от-github"       # можно noreply-адрес из Settings → Emails
git config --global credential.helper store
git clone https://github.com/Svalbard1/legal-assistant.git
cd legal-assistant
git switch -c fe/gulsym
git push -u origin fe/gulsym
```

Пароль от GitHub в git **не работает** — нужен токен (PAT): открой https://github.com/settings/tokens/new?scopes=repo&description=legal-assistant, галочка `repo` → Generate token → скопируй сразу (показывается один раз). При первом push: Username — твой ник на GitHub, Password — токен.

## 3. Важно понимать: в проекте два бэк-энда

- **ML-сервис** (уже работает): `http://localhost:8001`, Swagger на `/docs`, авторизации нет. Для прототипа интерфейса можно дергать его напрямую (CORS в dev открыт), но это временно.
- **Бекенд команды** (Лиза и Валя, ещё в разработке): будет на `/api/...` — с авторизацией, историей чатов, файлами. **В продуктовом коде фронт ходит только на него.**

Поле `llm` в ответе `/ask`: `"stub"` — пока возвращается выжимка источников без нейросети → показывай плашку «демо-режим»; `"vllm"` (историческое имя значения) — подключён настоящий LLM.

## 4. План работ

**Фаза 1 — прототип (можно начинать сегодня):**
- React-приложение в `frontend/` (Vite), экран чата
- ввод вопроса → `POST /ask` → показ `answer` + список источников (`sources`: имя файла, фрагмент, score) с возможностью раскрыть текст
- плашка «демо-режим», когда `llm == "stub"`
- экран загрузки документа: file input → `POST /ingest` (multipart, поле `file`) → сообщение «проиндексировано, N чанков»
- для прототипа подними ML-сервис локально (команды в `ml/docs/BACKEND_INTEGRATION.md`, раздел 0) или попроси Svalbard1 поднять и дать адрес

**Фаза 2 — переход на бекенд:**
- когда у Лизы/Вали готов `/api/ask` с auth — переключить base URL на бекенд, добавить экран логина
- обработка 401 (редирект на логин) и 502/504 (вежливое «сервис перегружен, попробуйте позже»)

**Фаза 3 — по мере готовности бекенда:**
- история диалогов, статусы обработки документов, стриминг ответа (если договоримся в контракте)

## Спецификация данных для ИИ-агента фронта (точные формы)

Продуктово фронт ходит ТОЛЬКО на backend (`/api/...`). Для прототипа можно напрямую в ML
(`http://localhost:8001`, CORS открыт). Формы данных ниже бекенд проксирует 1:1.

`POST /ask` → 200 (application/json):
```json
{
  "answer": "string — текст ответа; при llm=stub это выжимка источников, не генерация",
  "sources": [
    { "file": "string — имя документа (заголовок карточки источника)",
      "text": "string — фрагмент ≤ ~500 символов (раскрываемый текст)",
      "score": 0.6921,
      "page": 4 },
  ],
  "took_ms": 812,
  "llm": "stub"
}
```

Обязательные состояния UI:
- `llm == "stub"` → постоянная плашка «Демо-режим: ответ собран из найденных фрагментов»;
- `sources` — список карточек по убыванию score: заголовок `file`, раскрывающийся `text`,
  `score` (0–1) можно показывать как «релевантность»;
- ошибки читаются из `{"detail": string}`: 422 — ошибка формы, 404 — «ничего не найдено»,
  503 — «база пуста, загрузите документы», 502/504 — «сервис недоступен, попробуйте позже»;
- загрузка документа: `POST /ingest`, multipart, поле `file`; валидация ДО отправки:
  форматы `.pdf/.docx/.txt/.md`, ≤ 25 МБ; успех → «Проиндексировано: {chunks} фрагментов»;
  обработка 2–60 с — показывать индикатор прогресса;
- auth в ML нет; история чатов появится в v0.2 через backend.
