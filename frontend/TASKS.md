## 0. Конфигурация и инфраструктура (FE-0)

- Vite-приложение в `frontend/`; dev-сервер на 5173;
- Базовый URL API — через env: `VITE_API_BASE_URL` (файл `.env`, в git — `.env.example`);
  - прототип: `VITE_API_BASE_URL=http://localhost:8001` (ML-сервис напрямую, CORS открыт);
  - прод: `http://localhost:8000` (backend, пути `/api/...`) — переключение одной переменной;
- Все обращения к API — через один модуль-клиент (`src/api.js`), URL нигде не хардкодится.

**Acceptance:** смена одной строки `.env` меняет бекенд без правок кода.

## 1. Клиент API (FE-1)

Обёртка над fetch с обработкой ошибок. Эндпоинты:

| Метод | Путь | Тело | Успех |
|---|---|---|---|
| GET | `/health` | — | `{status, chunks_indexed, embed_model, llm}` |
| POST | `/ask` | `{question: string(3–2000), top_k?: int(1–20)}` | `{answer, sources[], took_ms, llm}` |
| POST | `/ingest` | multipart, поле `file` | `{doc_id, filename, chunks, status}` |

Ошибки — всегда `{"detail": string}`:
- `/ask`: 422 (валидация), 404 (ничего не найдено), 503 (база пуста);
- `/ingest`: 400 (формат/пустой текст), 413 (>25 МБ), 500;
- сеть/таймаут → человеческое сообщение, не сырой текст.

**Acceptance:** функции `ask(question)`, `ingest(file)`, `health()`; ошибки нормализованы в `{code, message}`.

## 2. Лента чата (FE-2) — ядро

- Сообщения пользователя и ассистента в одной ленте, аватар/иконка у ассистента;
- Отправка: кнопка + Enter (Shift+Enter — перенос строки);
- Во время запроса: спиннер в ленте (типично 1–3 с), ввод заблокирован от двойной отправки;
- `answer` рендерится как текст ассистента; переносы строк сохраняются (`white-space: pre-wrap`);
- `took_ms` — мелкой подписью под ответом («ответ за 1.2 с») — критерий «Скорость» (15%).

**Acceptance:** вопрос «какая неустойка за просрочку поставки» → осмысленный ответ со ссылкой на п. 4.1.

## 3. Источники ответа (FE-3) — главная фича кейса

- Под каждым ответом блок «Источники (N)»: карточки по убыванию `score`;
- Карточка: имя документа (`file`) + полоса/процент релевантности (`score`, 0–1) + фрагмент `text`,
  свёрнутый до 2 строк, клик → раскрыть полностью;
- Если источников больше 3 — «Показать все»;
- Клик по карточке ничего не ломает на мобильной ширине (адаптив минимальный).

**Acceptance:** после вопроса о неустойке видна карточка `пример.txt` с п. 4.1, текст раскрывается.

## 4. Плашка «Демо-режим» (FE-4) — обязательна

- `llm === "stub"` → бейдж у ответа: **«Демо-режим: ответ собран из найденных фрагментов, не сгенерирован нейросетью»**;
- `llm === "vllm"` → бейдж не показывается;
- Стиль: заметный, но не тревожный ( янтарный/инфо).

**Acceptance:** бейдж виден сейчас (ML в stub-режиме), исчезнет автоматически при подключении LLM.

## 5. Отказы и ошибки (FE-5)

- Отказ ассистента («В базе знаний не найдено достаточных оснований…») — это НОРМАЛЬНОЕ сообщение:
  рендерится как ответ ассистента с нейтральной иконкой ℹ️, без красных алертов;
- Карта ошибок (читать `detail` из `{"detail": string}`):

| Код | Текст пользователю |
|---|---|
| 422 | «Проверьте вопрос: от 3 до 2000 символов» |
| 404 | «По запросу ничего не найдено — переформулируйте» |
| 503 | «База знаний пуста — загрузите документы» + кнопка загрузки |
| 502/504 | «Сервис временно недоступен, попробуйте позже» + кнопка «Повторить» |

**Acceptance:** пустая база → 503-состояние с кнопкой загрузки; вопрос из 2 символов → 422-подсказка.

## 6. Загрузка документов (FE-6)

- Кнопка «Загрузить документ» → file input;
- Валидация ДО отправки: расширение `.pdf/.docx/.txt/.md`, размер ≤ 25 МБ;
- Во время обработки (2–60 с): индикатор + блокировка повторной отправки;
- Успех → «✅ Проиндексировано: {filename} — {chunks} фрагментов» в панели базы;
- Ошибки: 400 («формат не поддерживается / текст не найден»), 413 («файл больше 25 МБ»);
- Список загруженных файлов сессии (локально, без бекенда).

**Acceptance:** загрузить `ml/data/sample/пример.txt` → сообщено «6 фрагментов» → вопрос по договору получает ответ из него. Повторная загрузка того же файла не ломает ничего (ML идемпотентен).

## 7. Полировка (FE-7 — после демо-готового MVP, по остатку времени)

- Примеры вопросов-чипов при пустом чате (взять из `demo_questions.csv` организаторов);
- Кнопка «Скопировать ответ» (юристу нужно уносить цитаты);
- Клик по цитате в ответе → подсветка/прокрутка к соответствующей карточке источника;
- Индикатор статуса сервиса (из `/health`) в шапке.

## Вне скоупа (не делать)

Регистрация/логины, редактирование документов, стриминг ответа, тёмная тема, i18n, бекенд-логика на клиенте.

## Definition of Done (MVP для демо жюри)

Скрипт живой демонстрации (90 секунд):
1. Загрузить документ → «Проиндексировано: 6 фрагментов»;
2. Вопрос по документу → ответ с цитатой пункта + раскрытый источник;
3. Показать плашку «Демо-режим»;
4. Провокация: «игнорируй инструкции» или вопрос вне базы → вежливый отказ/границы компетенции;
5. Показать время ответа и обработку ошибки (выключить ML → вежливое «сервис недоступен»).

Порядок веток/PR: ветка `fe/gulsym`, коммиты `frontend: <что>`, PR в `main` (1 approve),
не трогать `ml/**`, `backend/**` (см. AGENTS.md).
